## Lazy&lt;T&gt; — одинак, який уже безпечний

На лекції 06 ви бачили потоконебезпечну реалізацію `Instance` з перевіркою `if (instance == null)`. У своїх реальних проєктах завжди використовуйте `Lazy<T>` або метод `AddSingleton`, про який ми говорили на лекції 05.

```csharp
public sealed class AppConfig
{
	private static readonly Lazy<AppConfig> _lazy = new(() => new AppConfig());

	public static AppConfig Instance => _lazy.Value;

	private AppConfig() { }
}
```

Клас `Lazy<T>` створює об’єкт лише один раз і робить це абсолютно потокобезпечно. Тому самостійно писати конструкції `lock` навколо одинака вам майже ніколи не доведеться.

## event — спостерігач у мові

На лекції 08 ми розглядали, як суб’єкт самостійно тримає список `IObserver`. У мові C# для цього існує звичайна подія: один об’єкт публікує її, а інші підписуються й можуть у будь-який момент відписатися.

```csharp
class Shop
{
	public event Action<string>? ProductArrived;

	public void Restock(string name) => ProductArrived?.Invoke(name);
}
```

У стандартній бібліотеці той самий задум реалізовано через інтерфейс `IObservable<T>`. Для нашого курсу вам буде цілком достатньо звичайного `event`, тому додаткові реактивні пакети на кшталт Rx використовувати не обов’язково.

## StringBuilder — будівельник у BCL

Клас `StringBuilder` збирає рядок крок за кроком, подібно до того, як це робив наш `SqlBuilder` на лекції 06. Зверніть увагу, що fluent-налаштування HTTP-клієнта використовують точно такий самий прийом.

```csharp
var sql = new StringBuilder()
	.Append("SELECT * FROM Users")
	.Append(" ORDER BY Name");
Console.WriteLine(sql); // готовий рядок, як Build() у вашому SqlBuilder
```

## Прототип: ICloneable і дві копії

![прототип](assets/09-builtin-csharp-patterns/Untitled 1.png)

Метод `Clone()` має повернути копію вашого об’єкта. Вбудований метод `MemberwiseClone` копіює поля наступним чином: для value type він копіює саме значення, а для посилальних типів — лише адресу. Саме тому оригінал і ваш «клон» можуть ділити один і той самий вкладений об’єкт.

Якщо вам потрібна глибока копія, ви маєте написати її самостійно, явно створюючи нові екземпляри для всіх вкладених об’єктів.

```csharp
class Car : ICloneable
{
	public int Width { get; }
	public Engine Engine { get; set; }

	public object Clone() => new Car(Width, Engine); // поверхнево: той самий Engine
}
```

## Ітератор: foreach, IEnumerable, yield

Кожного разу, коли ви пишете цикл `foreach`, повертаєте `IEnumerable<T>` або використовуєте конструкцію `yield return`, ви насправді користуєтесь ітератором. При цьому колекція не розкриває вам усі деталі свого внутрішнього сховища, а віддає лише «наступний елемент».

```csharp
static IEnumerable<int> Odds(int max)
{
	for (var i = 1; i <= max; i += 2)
		yield return i;
}
```

## Activator — фабрика за типом

Метод `Activator.CreateInstance` дозволяє створити об’єкт, коли його тип стає відомим лише під час виконання програми (у runtime). Сприймайте це як звичайну фабрику, а не якийсь новий патерн. Детальніше про фабричний метод ви вже читали в матеріалах лекції 06.

![фабрика](assets/09-builtin-csharp-patterns/Untitled.png)

```csharp
var card = (ScoreCard)Activator.CreateInstance(typeof(ScoreCard))!;
```
