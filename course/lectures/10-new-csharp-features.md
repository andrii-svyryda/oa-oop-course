## Кортежі замість одноразових DTO

Якщо вам треба повернути одразу два значення з методу, будь ласка, не створюйте для цього окремий клас.

```csharp
(string name, decimal price) Offer(string sku) => (sku, 19.99m);

var (name, price) = Offer("ABC");
var t = (Title: "OOP", Hours: 16);
```

Якщо ваша пара значень живе довго й має власну поведінку, тоді краще створіть повноцінний тип. Використовуйте tuple саме для короткої відповіді з методу.

## implicit / explicit operator

Тут ви самостійно задаєте правило перетворення між своїми типами. Пам’ятайте, що це не boxing. Boxing — це перетворення між value type та `object`, яке ми розглядали на лекції 02.

```csharp
public readonly struct Meters
{
	public double Value { get; }
	public Meters(double value) => Value = value;
	public static implicit operator Meters(double v) => new(v);
	public static explicit operator double(Meters m) => m.Value;
}

Meters m = 1.5;          // implicit: компілятор робить сам
double raw = (double)m;  // explicit: ви просите явно
```

Використовуйте `implicit` лише тоді, коли перетворення є абсолютно безпечним і не призводить до втрати даних. В усіх інших випадках завжди обирайте `explicit`.

## record і порівняння за значеннями

Тип `record` надзвичайно зручний для зберігання даних: порівняння об’єктів відбувається по їхніх полях, а не по посиланню в пам’яті. Крім того, ключове слово `with` дозволяє легко зробити копію об’єкта з однією чи кількома зміненими властивостями.

```csharp
public record Person(string Name, int Age);

var a = new Person("Ann", 20);
var b = a with { Age = 21 };
Console.WriteLine(a == new Person("Ann", 20)); // True
```

Конструкція `record struct` робить те саме, але для value type. Проте, якщо ваш об’єкт має багату поведінку та тривалий час життя, краще лишайте звичайний `class`.

## Pattern matching поруч із поліморфізмом

Конструкції patterns чудово читають форму ваших даних. Але класичну ієрархію типів лишайте для тієї поведінки, яку ви плануєте розширювати в майбутньому, дотримуючись принципу OCP з лекції 04.

```csharp
string Label(IShape s) => s switch
{
	Circle c => $"circle r={c.Radius}",
	Square sq => $"square {sq.Side}",
	_ => "unknown"
};
```

Додавання нового виду фігури змусить вас дописати нову гілку у `switch`. Якщо ж фігура має *робити* щось своє, тоді краще використати `virtual` методи або інтерфейс.
