Ви вже розібрали теорію GoF на лекціях 06–08. Сьогодні ми подивимося, де ці патерни вже є в BCL, щоб вам не доводилося писати зайвий код.

Що вже є в BCL

Ви вже користуєтесь цими патернами, можливо, не знаючи їхніх назв.

Singleton

Замість самописних блокувань використовуйте Lazy<T> — це готове потокобезпечне відкладене створення об’єктів.

Observer

Звичайний event — це і є класичний спостерігач. Один об’єкт публікує події, а інші на них підписуються.

Builder

Наприклад, StringBuilder або fluent-налаштування HTTP-клієнта збирають результат крок за кроком.

Ще три впізнавані шаблони

Prototype

Інтерфейс ICloneable та метод MemberwiseClone дозволяють клонувати об’єкт. Пам’ятайте, що це поверхнева копія, тому посилання на вкладені об’єкти лишаються спільними.

Iterator

Коли ви пишете цикл foreach, повертаєте IEnumerable або використовуєте yield, ви вже працюєте з ітератором.

Factory

Метод Activator.CreateInstance створює об’єкт за вказаним типом. Це звичайна фабрика, а не якийсь новий патерн.

Lazy<T> як одинак (Singleton)

Ось як тепер виглядає Singleton. Вам більше не потрібні самописні конструкції з lock, адже всю роботу бере на себе фреймворк.

public sealed class AppConfig {
  private static readonly Lazy<AppConfig> _lazy =
    new(() => new AppConfig());
  public static AppConfig Instance => _lazy.Value;
  private AppConfig() { /* конфіг лише раз */ }
}

event — спостерігач (Observer) у мові

На лекції 08 ви власноруч тримали список спостерігачів. У C# для цього є подія: ви можете легко підписатися на неї та відписатися.

class Shop {
  public event Action<string>? ProductArrived;
  public void Restock(string name) => ProductArrived?.Invoke(name);
}
shop.ProductArrived += msg => Console.WriteLine(msg);

Інтерфейс IObservable<T> реалізує той самий задум у стандартній бібліотеці. Зауважте, що окремий пакет Rx для нашого курсу вам не знадобиться.

Прототип (Prototype) і дві копії

Якщо вам потрібна копія об’єкта, просто реалізуйте ICloneable. Але завжди пам’ятайте, що поверхнева копія ділиться вкладеними об’єктами з оригіналом.

class Car : ICloneable {
  public Engine Engine { get; set; }
  public object Clone() => new Car { Engine = Engine };
}
// зміна clone.Engine змінить і оригінал
// глибоку копію пишете самі

Ітератор (Iterator): foreach і yield

Колекція віддає лише «наступний елемент», приховуючи внутрішню структуру.

static IEnumerable<int> Odds(int max) {
  for (var i = 1; i <= max; i += 2)
    yield return i;
}
foreach (var n in Odds(7)) 
  Console.WriteLine(n);
  • Коли: треба перебрати елементи складної структури (дерево, граф, масив), не розкриваючи її внутрішню будову клієнту.
  • Уникайте, коли: критично важлива максимальна продуктивність при роботі з простими масивами. Ітератор створює додатковий об'єкт стану в пам'яті, що вимагає роботи Garbage Collector-а. Якщо ви ітеруєте мільйони елементів у гарячому циклі, накладні витрати на абстракцію можуть стати помітними. Альтернатива: Прямий цикл for з індексом.

Питання для самоперевірки

Чи можете ви пояснити своїми словами ті концепції, які ми вже розглянули в курсі?

  • Стовпи ООП, різницю між virtual, override та overload, навіщо потрібен sealed, а також як працюють upcast і downcast.
  • Що таке boxing та constraints, які ми вивчали на лекції 02. Будь ласка, не плутайте їх з implicit operator.
  • Принципи SOLID своїми словами та розуміння того, навіщо нам потрібен IoC.

Повний список питань для підготовки до інтерв’ю ви знайдете в лабораторній 15 загального плану. Теми covariance та reflection також входять до цього списку, тому окремою лекцією ми їх не виносимо.
