Лекція 04

Принципи SOLID

П’ять правил, які роблять ієрархії класів придатними до змін.

SRPOCPLSPISPDIP

Перші три принципи

SRP

Одна причина змінювати клас. Email і валідація адреси — різні типи.

OCP

Відкритий до розширення, закритий до модифікації. Нова знижка — новий клас, не новий case.

LSP

Нащадок можна підставити замість батька без поломки програми.

ISP і DIP

ISP

Не змушуйте клієнта залежати від методів, яких він не використовує. Дрібні інтерфейси.

DIP

Модулі верхнього рівня залежать від абстракцій, не від деталей. Деталі залежать від абстракцій.

OCP: погано — switch по типу

public double CalculateDiscount(double price, CustomerType t) {
  switch (t) {
    case CustomerType.Regular: return price * 0.1;
    case CustomerType.Premium: return price * 0.3;
    case CustomerType.Newbie:  return price * 0.05;
    default: throw new ArgumentOutOfRangeException();
  }
} // кожен новий тип = правка цього методу

OCP: добре — стратегія

public interface IDiscountStrategy {
  double CalculateDiscount(double price);
}
public class DiscountCalculator {
  private readonly IDiscountStrategy _s;
  public DiscountCalculator(IDiscountStrategy s) => _s = s;
  public double CalculateDiscount(double price) => _s.CalculateDiscount(price);
}

LSP: Orange не є Apple

Порушення: Orange : Apple і GetColor() бреше про яблуко.

Apple apple = new Orange();
Console.WriteLine(apple.GetColor());

Виправлення: спільний контракт IFruit.

IFruit fruit = new Orange();
fruit = new Apple();

ISP: робот не їсть

interface IWorker {
  void Work();
  void Eat();
  void Sleep();
}
interface IWorkable { void Work(); }
interface IEatable { void Eat(); }
class RobotWorker : IWorkable { }

DIP: не new всередині бізнес-класу

public class EmployeeDetailsModified {
  private readonly ISalaryCalculator salaryCalculator;
  public EmployeeDetailsModified(ISalaryCalculator salaryCalculator)
    => this.salaryCalculator = salaryCalculator;
}

Варто розібрати

  • S — відправка email + валідатор адреси/теми
  • O — калькулятор площі / знижок
  • L — запис у файл різних форматів
  • I — базовий механізм і уточнені інтерфейси
  • D — логер Trace / Log / Information / Exception
