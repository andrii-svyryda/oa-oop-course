Гнучке створення об’єктів без розкиданих new і зайвих залежностей.

Патерн ≠ алгоритм

  • Алгоритм — чіткі кроки (рецепт)
  • Патерн — креслення рішення; код щоразу підлаштовують
  • GoF («банда чотирьох»): породжувальні, структурні, поведінкові

Три сім’ї GoF

Породжувальні

Як створювати об’єкти, не прив’язуючись до конкретних класів.

Структурні

Як складати об’єкти в більші структури.

Поведінкові

Як об’єкти спілкуються і розподіляють обов’язки.

Абстрактна фабрика

Сім’ї сумісних продуктів без вказання конкретних класів.

Фабричний метод

Виносимо new у перевизначуваний метод підкласу.

  • Клієнт залежить від абстракції продукту
  • У .NET поруч: DbProviderFactory, LoggerFactory, Activator.CreateInstance
  • Детальніше — лекція про вбудовані шаблони C#

Одинак — і чому «проста» версія небезпечна

  • Один екземпляр + глобальна точка доступу
  • Зазвичай lazy, без параметрів конструктора
  • Код справа — не thread-safe
  • Краще Lazy<T> або контейнер Singleton
public sealed class Singleton {
  private static Singleton instance;
  private Singleton() {}
  public static Singleton Instance {
    get {
      if (instance == null)
        instance = new Singleton();
      return instance;
    }
  }
}
