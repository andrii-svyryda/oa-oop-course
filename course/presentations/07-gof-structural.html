Структурні патерни GoF

Обгортки, спрощені фасади й дерева однотипних вузлів.

DecoratorFacadeAdapterComposite

Декоратор

Той самий контракт, додаткова поведінка без зміни оригіналу.

  • Retry, logging, кеш, шифрування потоку
  • Рекурсивний: декоратор на декоратор
  • Клієнт не знає, що викликає обгортку

Ланцюжок відповідальності навколо IMessenger

public interface IMessenger {
  void Send(Message message);
  Message Receive();
}
// LoggingMessenger : IMessenger
// RetryMessenger : IMessenger
// обидва тримають inner IMessenger

Фасад

  • Простий інтерфейс до складної підсистеми
  • PlaceOrder: Product + Payment + Invoice в одному методі
  • Клієнт не збирає оркестрацію сам

Adapter і Composite

Adapter

Чужий інтерфейс → потрібний контракт. Старий логер під ILogger.

Composite

Листок і група з одним інтерфейсом. IGraphic: Circle і GroupOfGraphics.

Коли який

  • Треба додати поведінку навколо існуючого об’єкта → Decorator
  • Занадто багато класів, щоб зробити «одну дію» → Facade
  • Несумісні інтерфейси → Adapter
  • Дерево однотипних елементів → Composite
