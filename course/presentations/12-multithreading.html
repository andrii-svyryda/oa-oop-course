Багатопотоковість у C#

Паралельність дає швидкість і гонки. Синхронізація — плата за спільний стан.

ThreadThreadPoollockasync

Процес і потік

  • Однопроцесорні ОС і витісняюча багатозадачність (Win95 як приклад)
  • Процес = адресний простір; потоків у ньому багато
  • У кожного процесу є головний потік

Свій Thread

Thread t = new Thread(Worker);
t.Start();                 // не блокує Main
for (int i = 0; i < 10; i++) {
  Console.WriteLine("Main");
  Thread.Sleep(100);
}
t.Join();                  // дочекатись Worker

ThreadPool

Пул повторно використовує потоки. Не створюйте Thread на кожне дрібне завдання.

ThreadPool.QueueUserWorkItem(Worker, "Hello, world!");

Гонка без lock

public void PrintTable() {
  for (int i = 1; i <= 10; i++) {
    Thread.Sleep(100);
    Console.WriteLine(i);
  }
}
// два потоки друкують впереміш
public void PrintTable() {
  lock (this) { /* критична секція */ }
}
// також: Mutex, Semaphore
// lock(this) у бібліотеках — погана практика;
// краще private readonly object _sync = new();

Task і async/await

  • Потік керує ОС; Task — середовище виконання
  • Винятки в Task структурованіші, ніж « dig в чужому потоці»
  • TAP: async Task + await
static async Task Main() {
  Task task1 = Task.Run(
    () => Console.WriteLine("work"));
  await task1;
  Console.WriteLine("Task completed!");
}

Зв’язок з іншими темами

Thread-safety одинака (Lazy<T>) і спільний стан у чаті — типові місця, де ця лекція проявляється. Окремої лабораторної з потоків немає.
