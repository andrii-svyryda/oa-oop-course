Лекція 02

Узагальнення (generics)

Згадаємо роботу з типами та їх приведення, щоб зрозуміти, навіщо нам <T>.

value / referencecastboxing<T>

План заняття

  • Згадаємо різницю між value та reference type, щоб ви побачили, звідки береться boxing.
  • Подивимось, як працює приведення типів і що відбувається, коли ви кладете value type в object.
  • Спробуємо колекцію object і побачимо, як легко програма падає в runtime.
  • Розберемо generics: як написати метод чи клас із <T> та як поставити на нього constraints.
  • Колекції сьогодні згадуємо лише як приклад, а яку саме структуру обрати — розберемо на лекції 11.

Value type і reference type

Value type — int, bool, double, struct, enum

  • Значення лежить прямо у вашій змінній.
  • Коли ви щось присвоюєте, дані просто копіюються.
  • Маєте дві змінні — маєте два незалежні числа 42.

Reference type — class, масиви, більшість BCL

  • Змінна тримає лише вказівник на об’єкт, який живе на heap.
  • Дві змінні можуть дивитися на один і той самий об’єкт.
  • string — це теж reference type, але він незмінний.

Ви можете покласти будь-який тип у змінну типу object. Але для value type CLR кладе копію на heap, і це не безкоштовно.

Приведення типів (cast)

  • Неявне (implicit) — це безпечне розширення. Компілятор робить це сам, бо ви нічого не втратите.
  • Явне (explicit) — тут відповідальність на вас. Ви кажете компілятору: «я знаю, що роблю».
  • Upcast та downcast між класами ми вже розібрали на першій лекції.
  • Якщо ви помилилися з типом, програма впаде з InvalidCastException, коли вже працюватиме.
long wide = 42;      // неявно: int → long
int narrow = (int)wide; // явно: можна втратити дані

object box = 10;
int n = (int)box;    // ок, якщо всередині int
string s = (string)box; // виняток у runtime

Boxing і unboxing

  • Boxing — коли ви кладете int в object, на heap з’являється обгортка і туди копіюється значення.
  • Unboxing — коли ви дістаєте значення назад, вам потрібен точний тип.
  • Запакований int — це не long. Ви не можете дістати його як інший тип.
int n = 42;
object box = n;        // boxing
int copy = (int)box;   // unboxing
long fail = (long)box; // InvalidCastException

Не плутайте це з implicit чи explicit operator. Як писати власні оператори перетворення, ми подивимось на лекції 10.

Без generics: усе як object

var items = new List<object>(); // раніше — ArrayList
items.Add(10);      // boxing: int → object
items.Add("oops");  // компілятор мовчить
int x = (int)items[0]; // unboxing + cast — ок
int y = (int)items[1]; // бум: рядок не є int

Компілятор дозволяє вам змішати числа й рядки, а програма падає в runtime. Саме цю проблему вирішують generics.

Навіщо generics

  • Безпека типів. Якщо ви спробуєте покласти рядок у список чисел, компілятор це не пропустить.
  • Продуктивність. Коли ви створюєте List<int>, він зберігає числа саме як числа, тому ви уникаєте boxing.
  • Повторне використання. Ви пишете алгоритм один раз, і він працює для int, string чи ваших власних класів.

Узагальнений метод Swap

Тут T працює як замінник: коли ви викликаєте метод, компілятор підставляє замість T ваш реальний тип.

public static void Swap<T>(ref T one, ref T second) {
  T tmp = one;
  one = second;
  second = tmp;
}

Swap<int>(ref a, ref b);
Swap(ref c, ref d); // компілятор виведе T

Узагальнений клас

Ви можете зробити весь клас узагальненим, і тоді T буде відомим для всіх його методів та полів.

public class VerySimpleAndNaiveCache<T> {
  private Dictionary<string, T> cache = new();

  public T GetOrCreate(string key, Func<T> createItem) {
    if (!cache.ContainsKey(key))
      cache[key] = createItem();
    return cache[key];
  }
}

var usersCache = new VerySimpleAndNaiveCache<UserCacheItem>();

Обмеження (constraints)

Компілятор має знати, що ваш T вміє робити. Ви ставите constraint, коли вам потрібна конкретна поведінка.

  • Пишіть where T : struct, якщо ваш код працює лише з value type.
  • Пишіть where T : class, якщо вам потрібен саме reference type.
  • Додавайте where T : new(), щоб ви могли створити об’єкт через new T().
  • Ви також можете вимагати, щоб T реалізував певний інтерфейс чи наслідував базовий клас.
public static void Swap<T>(ref T a, ref T b) where T : struct

Колекції — приклад, не вся тема

  • Стандартні колекції є узагальненими, тому List<int> завжди залишатиметься списком чисел і не прийме рядок.
  • Делегати Func та Action, які ви бачили на першій лекції, теж працюють через generics.
  • Сьогодні ми не обираємо між списком, словником чи стеком — про це детально поговоримо на лекції 11.

Підсумок

  • Коли ви присвоюєте value type, ви копіюєте самі дані. Для reference type ви копіюєте лише посилання.
  • Коли ви кладете value type в object, на heap з’являється обгортка, і це не безкоштовно.
  • Generics дозволяють вам писати безпечний код, який не робить зайвого boxing та не падає в runtime.
  • Якщо ви ловите себе на тому, що копіюєте той самий код для різних типів — час написати метод із T.
