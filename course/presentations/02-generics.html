Лекція 02

Узагальнення (generics)

Один алгоритм — багато типів, без кастингу і дублювання коду.

<T>constraintsList / Dictionary

Навіщо generics

  • Безпека типів на етапі компіляції
  • Продуктивність — немає boxing / зайвого cast
  • Повторне використання — один код для int, string, своїх класів

Узагальнений метод Swap

public static void Swap<T>(ref T one, ref T second) {
  T tmp = one;
  one = second;
  second = tmp;
}

Swap<int>(ref a, ref b);
Swap(ref c, ref d); // компілятор виведе T

Узагальнений клас

public class VerySimpleAndNaiveCache<T> {
  private Dictionary<string, T> cache = new();

  public T GetOrCreate(string key, Func<T> createItem) {
    if (!cache.ContainsKey(key))
      cache[key] = createItem();
    return cache[key];
  }
}

var usersCache = new VerySimpleAndNaiveCache<UserCacheItem>();

Обмеження (constraints)

  • where T : struct — value type
  • where T : class — reference type
  • where T : new() — є конструктор без параметрів
  • where T : Enum, notnull, конкретний базовий клас / інтерфейс
public static void Swap<T>(ref T a, ref T b) where T : struct

Колекції як головний приклад

  • List<T> — індексований динамічний список
  • Dictionary<TKey,TValue> — пари ключ–значення
  • Queue<T> FIFO · Stack<T> LIFO
  • Делегати Func<> / Action<> теж generic

Підсумок

Якщо бачите copy-paste під int і double — майже завжди потрібен T з правильним constraint.
