Абстракція

Приховуємо деталі імплементації й лишаємо лише головні характеристики об’єкта.

  • Мета — спростити розуміння, не «показати все»
  • У C# абстракції будують абстрактні класи та інтерфейси

Абстрактний клас

  • Не можна створити екземпляр
  • Може мати абстрактні методи й властивості
  • Нащадок мусить реалізувати всі абстрактні члени
  • Немає abstract static — static належить типу, не об’єкту
abstract class Shape {
  public abstract int GetArea();
}

class Square : Shape {
  private readonly int sideSize;
  public Square(int size) => sideSize = size;
  public override int GetArea() => sideSize * sideSize;
}

Інтерфейс — контракт

  • Методи, властивості, індексатори, події
  • Клас / record / struct зобов’язані реалізувати контракт
  • Не інстанціюємо інтерфейс
  • Клієнт працює з абстракцією: масив IShapeAreaCalculator[]
interface IShapeAreaCalculator {
  double GetArea();
  string WhoAmI { get; }
}

class Circle : IShapeAreaCalculator {
  public double GetArea() => Math.PI * r * r;
  public string WhoAmI => GetType().ToString();
}

Default interface methods

Реалізація за замовчуванням у інтерфейсі: спільний алгоритм спирається на абстрактні кроки.

interface ISecureCardReader {
  void InitializeCardReader();
  void CloseCardReader();
  string NativeRead();

  string SecureRead() {
    InitializeCardReader();
    var n = NativeRead();
    CloseCardReader();
    return Mask(n);
  }
}

Інкапсуляція

  • Внутрішній стан прихований
  • Доступ лише через публічний інтерфейс
  • Модифікатори: public, private, protected, internal
  • Публічне поле ламає контроль; публічна властивість — ні
public class Account {
  private decimal balance;
  public decimal Balance => balance;

  public void Withdraw(decimal amount) {
    if (balance < amount)
      throw new Exception("Insufficient funds");
    balance -= amount;
  }
}

Наслідування

  • Похідний клас повторно використовує й розширює базовий
  • Доступні public / protected / internal; private — ні
  • virtual + override; звертання до батька — base
  • sealed забороняє наслідування або подальше override
  • Немає множинного наслідування класів — лише багато інтерфейсів

Приклад: Person → Student / Teacher

public class Student : Person {
  public string StudentEmail { get; private set; }
  public Student(string name, int age, string address, string email)
      : base(name, age, address) {
    StudentEmail = email;
  }
}

Поліморфізм

Статичний (компіляція)

  • перевантаження методів
  • перевантаження операторів

Динамічний (runtime)

  • virtual / override
  • виклик через базовий тип запускає метод нащадка
public int Add(int a, int b) => a + b;
public double Add(double a, double b) => a + b;

List<Shape> shapes = [new Rectangle(...), new Triangle(...)];
foreach (var s in shapes) s.Draw(); // динамічний

Розширювальні методи

  • Статичний клас, перший параметр з this
  • Виклик як у члена типу
  • Існуючий метод типу має пріоритет
  • Типовий приклад: розбити рядок на слова й порахувати їх
public static class StringExtension {
  public static string[] ToWords(this string str)
    => str.Split([' ', '.', '?'],
         StringSplitOptions.RemoveEmptyEntries);
  public static int WordsCount(this string str)
    => str.ToWords().Length;
}

LINQ стоїть на трьох ніжках

Extension methods

Where, Select — методи розширення IEnumerable

Делегати

Func, Action, Predicate — колбеки для фільтрів

yield

Відкладене виконання: елемент з’являється лише коли його просять

Делегат як точка розширення

public delegate List<string> ParseCardNumber(string cardNumber);

public string Mask(string cardNumber, ParseCardNumber parse = null) {
  var groups = parse != null ? parse(cardNumber) : SplitBy4(cardNumber);
  return $"{groups[0]} **** **** {groups[^1]}";
}
// або Func<string, List<string>>

Підсумок

  • Працюйте через контракти, не через конкретні класи
  • Стан ховайте; властивості дають місце для інваріантів
  • Поліморфізм = одна назва, різна поведінка
  • LINQ — не магія, а extensions + делегати + yield
