Теорія ООП

Чотири стовпи ООП, розширювальні методи, делегати та LINQ — база, на якій тримається весь курс.

Про що сьогодні поговоримо

  • Подивимось, як абстрактні класи та інтерфейси (навіть із default methods) допомагають будувати гнучку архітектуру.
  • Розберемо, чому інкапсуляція — це не просто приватні поля, а надійний публічний контракт.
  • Пройдемо наслідування та ключові слова base, virtual і sealed.
  • Зрозуміємо поліморфізм: як працюють overload та override, і чим відрізняються upcast і downcast.
  • І наостанок — як extension methods, делегати та yield лежать в основі LINQ.

Абстракція

Ми приховуємо зайві деталі реалізації, щоб залишити лише те, що дійсно важливо для нашої задачі.

  • Наша мета — спростити використання коду, а не виставляти назовні всі деталі системи.
  • У C# ми будуємо такі абстракції за допомогою абстрактних класів та інтерфейсів.

Абстрактний клас

  • Ви не можете створити екземпляр абстрактного класу — це лише шаблон для інших.
  • Він дозволяє описати абстрактні методи й властивості, які не мають тіла.
  • Якщо ви наслідуєте такий клас, ви зобов’язані реалізувати всі його абстрактні члени.
  • До речі, abstract static не буває, бо статика належить типу, а не конкретному об’єкту.
abstract class Shape {
  public abstract int GetArea();
}

class Square : Shape {
  private readonly int sideSize;
  public Square(int size) => sideSize = size;
  public override int GetArea() => sideSize * sideSize;
}

Інтерфейс — це суворий контракт

  • Він лише описує, що має вміти тип: які там є методи, властивості чи події.
  • Будь-який клас, record чи struct, що підписує цей контракт, зобов’язаний його виконати.
  • Ви не можете створити екземпляр самого інтерфейсу, бо там немає реалізації.
  • Зате ваш код може працювати з абстракцією, наприклад, приймати масив IShapeAreaCalculator[], не знаючи конкретних фігур.
interface IShapeAreaCalculator {
  double GetArea();
  string WhoAmI { get; }
}

class Circle : IShapeAreaCalculator {
  public double GetArea() => Math.PI * r * r;
  public string WhoAmI => GetType().ToString();
}

Default interface methods

Іноді зручно дати інтерфейсу дефолтну реалізацію: ми пишемо спільний алгоритм, який викликає інші, ще не реалізовані методи.

interface ISecureCardReader {
  void InitializeCardReader();
  void CloseCardReader();
  string NativeRead();

  string SecureRead() {
    InitializeCardReader();
    var n = NativeRead();
    CloseCardReader();
    return Mask(n);
  }
}

Інкапсуляція

  • Ми ховаємо внутрішній стан об’єкта, щоб ніхто не міг зламати його ззовні.
  • Увесь доступ іде лише через чітко визначений публічний інтерфейс.
  • Для цього ми використовуємо модифікатори доступу: public, private, protected, internal.
  • Ніколи не робіть поля публічними — ви втратите контроль над даними. Використовуйте властивості, щоб перевіряти значення перед записом.
public class Account {
  private decimal balance;
  public decimal Balance => balance;

  public void Withdraw(decimal amount) {
    if (balance < amount)
      throw new Exception("Insufficient funds");
    balance -= amount;
  }
}

Наслідування

  • Ви створюєте похідний клас, щоб не писати код з нуля, а перевикористати й розширити базовий.
  • Нащадку доступно все, що public, protected або internal, але private залишається таємницею батька.
  • Щоб змінити поведінку, ми використовуємо virtual та override, а до старого коду звертаємось через base.
  • Якщо хочете заборонити наслідування вашого класу, просто додайте sealed.
  • У C# немає множинного наслідування класів, щоб уникнути хаосу — натомість реалізовуйте скільки завгодно інтерфейсів.
  • Про те, коли варто наслідувати, а коли краще просто «мати всередині» (композиція) — ми детально поговоримо на третій лекції.

Приклад: Person → Student

Зверніть увагу, як конструктор студента передає базові дані в конструктор Person через base, а сам ініціалізує лише своє.

public class Student : Person {
  public string StudentEmail { get; private set; }
  public Student(string name, int age, string address, string email)
      : base(name, age, address) {
    StudentEmail = email;
  }
}

Поліморфізм

Статичний (компілятор обирає під час збірки)

  • Перевантаження методів (overload): компілятор дивиться на типи аргументів і підставляє правильний метод.
  • Перевантаження операторів.

Динамічний (runtime обирає під час виконання)

  • Працює через virtual та override.
  • Коли ви викликаєте метод через базовий тип, програма сама розуміє, який об’єкт там насправді, і запускає метод нащадка.
public int Add(int a, int b) => a + b;
public double Add(double a, double b) => a + b;

List<Shape> shapes = [new Rectangle(...), new Triangle(...)];
foreach (var s in shapes) s.Draw(); // динамічний

Upcast і downcast

Upcast — це перехід від нащадка до батька. Це завжди безпечно: квадрат гарантовано є фігурою.

Shape s = new Square(3);
s.GetArea();

Downcast — від батька до нащадка. Це небезпечно: не кожна фігура є квадратом, тому програма може впасти.

Square sq = (Square)s;
Square? ok = s as Square;
if (s is Square square) { }
  • Увесь поліморфізм тримається на upcast: ми складаємо різні фігури в один список Shape і працюємо з ними однаково.
  • Якщо вам конче треба зробити downcast, використовуйте is або as, щоб уникнути помилок під час виконання.
  • А от перетворення value type в object — це вже boxing. Про нього поговоримо на наступній лекції.

Розширювальні методи

  • Ви можете додати нові методи до чужих класів, створивши статичний метод із ключовим словом this перед першим параметром.
  • У коді це виглядає так, ніби метод завжди був частиною цього типу.
  • Але пам’ятайте: якщо в класі вже є метод із таким самим ім’ям, він матиме пріоритет.
  • Типовий приклад: ми вчимо звичайний рядок розбиватися на слова та рахувати їхню кількість.
public static class StringExtension {
  public static string[] ToWords(this string str)
    => str.Split([' ', '.', '?'],
         StringSplitOptions.RemoveEmptyEntries);
  public static int WordsCount(this string str)
    => str.ToWords().Length;
}

LINQ стоїть на трьох ніжках

Extension methods

Усі ці Where та Select — це просто зручні методи розширення для інтерфейсу IEnumerable.

Делегати

Ми передаємо логіку фільтрації прямо в метод, використовуючи делегати на кшталт Func чи Predicate.

yield

Завдяки відкладеному виконанню, наступний елемент колекції обчислюється лише тоді, коли він нам дійсно потрібен.

Делегат як точка розширення

Делегати дозволяють передавати функції як параметри. Це ідеальний спосіб дати клієнту можливість підмінити частину вашого алгоритму.

public delegate List<string> ParseCardNumber(string cardNumber);

public string Mask(string cardNumber, ParseCardNumber parse = null) {
  var groups = parse != null ? parse(cardNumber) : SplitBy4(cardNumber);
  return $"{groups[0]} **** **** {groups[^1]}";
}
// або Func<string, List<string>>

Підсумок

  • Завжди намагайтеся працювати через контракти (інтерфейси), а не зав’язуватися на конкретні класи.
  • Ховайте внутрішній стан об’єктів. Використовуйте властивості, щоб гарантувати, що ваші дані завжди валідні.
  • Пам’ятайте, що поліморфізм дозволяє викликати один метод, але отримувати різну поведінку. І все це працює завдяки upcast.
  • LINQ здається магією, але насправді це просто елегантна комбінація extension methods, делегатів та yield.
