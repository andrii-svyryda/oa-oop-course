Нові можливості C# та ООП

Сучасний синтаксис жодним чином не скасовує принципи ООП — він просто дозволяє вам писати код коротше та виразніше.

tuplesrecordsoperatorspatterns

Навіщо нам ця лекція

Ми навчимося писати менше шаблонного коду.

  • Сучасний C# дозволяє вам описувати моделі набагато лаконічніше.
  • Наша головна мета — перестати плодити зайві DTO і не ламати інкапсуляцію лише заради зручності.
  • Ми з вами вже розібрали базове ООП, generics та default methods. Сьогодні ми подивимося на зручний синтаксис, який побудований навколо них.

Кортежі замість одноразових DTO

Вам потрібно повернути одразу два значення з методу? Будь ласка, не створюйте для цього окремий клас, а просто візьміть кортеж (tuple).

(string name, decimal price) Offer(string sku) => (sku, 19.99m);

var (name, price) = Offer("ABC");
var t = (Title: "OOP", Hours: 16);
Console.WriteLine($"{t.Title}: {t.Hours} год");

implicit / explicit operator

Ви можете навчити ваші власні типи перетворюватися один в одного.

Зверніть увагу: це зовсім не boxing. Механізм boxing ми вивчали на лекції 02 (це коли value type пакується в object). Тут ви самостійно задаєте чітке правило перетворення між своїми типами.

public readonly struct Meters {
  public double Value { get; }
  public Meters(double value) => Value = value;
  public static implicit operator Meters(double v) => new(v);
  public static explicit operator double(Meters m) => m.Value;
}
Meters m = 1.5;          // implicit: компілятор робить це сам
double raw = (double)m;  // explicit: ми явно просимо перетворення

record і value-based equality

Типи record ідеально підходять для зберігання даних. Вони автоматично порівнюються саме за значеннями своїх полів, а не за посиланнями в пам’яті.

public record Person(string Name, int Age);
public record struct Point(int X, int Y);

var a = new Person("Ann", 20);
var b = a with { Age = 21 }; // створюємо незмінну копію з новою властивістю
Console.WriteLine(a == new Person("Ann", 20)); // True, бо дані однакові

Pattern matching поруч із поліморфізмом

Pattern matching — чудовий інструмент для обробки даних. Проте пам'ятайте: якщо ви плануєте розширювати логіку в майбутньому, класична ієрархія класів залишається найкращим вибором.

string Label(IShape s) => s switch {
  Circle c => $"circle r={c.Radius}",
  Square sq => $"square {sq.Side}",
  _ => "unknown"
};

Default interface methods

Інтерфейси в C# можуть містити реалізацію методів за замовчуванням. Це розширює їхні можливості, дозволяючи додавати поведінку прямо в контракт.

  • Безпечне розширення API: додавання нових методів без поломки існуючих реалізацій.
  • Спільна логіка: базовий алгоритм безпосередньо в інтерфейсі без дублювання.

На відміну від абстрактних класів: інтерфейси не можуть містити полів (стану) та конструкторів, але один клас може реалізовувати одразу декілька інтерфейсів із дефолтними методами (множинне успадкування поведінки).

public interface ILogger {
  void Log(string message); // Звичайний метод

  // Метод за замовчуванням (Default interface method)
  void LogError(string error) => Log($"[ERROR] {error}");
}
