Щільне зв’язування

Зміна логера змушує чіпати MessageProcessor.

public class MessageProcessorForTightCoupling {
  private LogManager logManager;
  public MessageProcessorForTightCoupling() {
    this.logManager = new LogManager(); // сам створив
  }
}

Слабке зв’язування і DI

  • Створення об’єктів відокремлене від їх використання
  • Клієнт не знає, як зібрати сервіс
  • Залежність передають (constructor / method / property injection)
  • DI ≠ DIP, але DI — типовий спосіб дотримати DIP

Контейнер Microsoft.Extensions.DependencyInjection

using IHost host = Host.CreateDefaultBuilder()
  .ConfigureServices((_, services) => {
    services.AddSingleton<IEmailNotification, EmailNotification>();
    services.AddSingleton<NotificationService>();
  }).Build();

var sender = host.Services.GetService<NotificationService>();
sender.PushNotification("DI is not DIP");

Service lifetimes

Transient

Новий екземпляр на кожен запит із контейнера.

Scoped

Один екземпляр на scope / HTTP-запит. Типово для web.

Singleton

Один екземпляр на весь час життя застосунку.

Варто розібрати

Worker, який обробляє дані залежно від типу роботи: конкретну стратегію роботи йому передають, він її не створює.
