Колекції в C#

Обирайте колекцію за типом доступу, а не ту, що першою спала на думку.

ListDictionaryHashSetStack / Queue

Що ви вже знаєте, а що ми розберемо сьогодні

Сьогодні ми не повторюємо generics, а зосередимося на тому, як вам обрати правильну структуру даних.

  • На лекції 02 ви вже розібрали, чому варто використовувати List<T>, а не застарілий ArrayList чи List<object>.
  • Сьогодні ми поговоримо про те, як працює хеш і звідки беруться колізії.
  • Також ви дізнаєтеся, коли брати HashSet або SortedSet, і для яких задач ідеально підходять Stack та Queue.

Коли варто брати List<T>

Беріть список, коли вам важливий порядок елементів, ви хочете звертатися до них за індексом, і колекція буде рости. Але якщо ви шукаєте за ключем — List вам не підійде.

List<string> dirs = new(Directory.EnumerateDirectories(docPath));
foreach (var dir in dirs) Console.WriteLine(Path.GetFileName(dir));

Dictionary і хеш-функції

Словник — це швидкий пошук значення за унікальним ключем.

  • Dictionary працює так швидко завдяки пошуку через hash code.
  • Іноді трапляються колізії: це ситуація, коли кілька різних ключів потрапляють у один кошик.
  • Саме тому ваші методи Equals та GetHashCode завжди мають бути узгоджені.
static int HashFunction(string s, string[] array) {
  int total = 0;
  foreach (char c in s) total += c;
  return total % array.Length; // дуже спрощений приклад хеш-функції
}

HashSet проти SortedSet

Ці колекції стануть у пригоді, коли вам потрібна лише множина унікальних елементів.

HashSet гарантує унікальність, але не зберігає порядок. Зате ви миттєво зробите математичні операції: об’єднання (union), перетин (intersect) чи різницю (except).

SortedSet теж зберігає лише унікальні елементи, але одразу сортує їх за зростанням. Вставка сюди обійдеться вам дорожче, зате ви завжди маєте відсортований набір.

Stack і Queue

Це дві класичні структури для ваших специфічних задач.

Stack працює за принципом LIFO (останній зайшов — перший вийшов). Він ідеально підійде вам для скасування дій (undo) або обходу в глибину (DFS).

Queue — це FIFO (перший зайшов — перший вийшов). Використовуйте його для черги задач, обходу в ширину (BFS) або фонових робіт.

stack.Push(x); var y = stack.Pop();
queue.Enqueue(x); var z = queue.Dequeue();

Пам’ятка: як обрати колекцію

Завжди задавайте собі питання: як саме ви будете з нею працювати?

  • Якщо вам потрібен індекс і збереження порядку, беріть List<T>.
  • Якщо ви шукаєте значення за ключем, ваш вибір — Dictionary<TKey,TValue>.
  • Якщо вам важлива лише унікальність, використовуйте HashSet<T>. А якщо елементи мають бути ще й відсортовані — беріть SortedSet<T>.
  • Для принципу «останній зайшов — перший вийшов» обирайте Stack<T>. А для принципу «перший зайшов — перший вийшов» вам знадобиться Queue<T>.
