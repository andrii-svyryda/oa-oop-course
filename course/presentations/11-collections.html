Колекції в C#

Обирайте колекцію за типом доступу, а не ту, що першою спала на думку.

ListDictionaryHashSetStack / Queue

Що ми вже знаємо, а що розберемо сьогодні

Ми не будемо повторювати generics. Зосередимось на виборі правильної структури даних.

  • На лекції 02 ми вже розібрали, чому варто використовувати List<T>, а не застарілий ArrayList чи List<object>.
  • Сьогодні ми поговоримо про те, як працює хеш і що таке колізії.
  • Також розберемося, коли брати HashSet або SortedSet, і для яких задач ідеально підходять Stack та Queue.

Коли варто брати List<T>

Беріть список, коли вам важливий порядок елементів, ви хочете звертатися до них за індексом, і колекція буде рости. Але якщо ви шукаєте за ключем — List вам не підійде.

List<string> dirs = new(Directory.EnumerateDirectories(docPath));
foreach (var dir in dirs) Console.WriteLine(Path.GetFileName(dir));

Dictionary і хеш-функції

Словник — це швидкий пошук значення за унікальним ключем.

  • Він працює так швидко завдяки пошуку через hash code.
  • Іноді трапляються колізії: це коли кілька різних ключів потрапляють у один кошик.
  • Саме тому ваші методи Equals та GetHashCode завжди мають бути узгоджені.
static int HashFunction(string s, string[] array) {
  int total = 0;
  foreach (char c in s) total += c;
  return total % array.Length; // дуже спрощений приклад хеш-функції
}

HashSet проти SortedSet

Коли вам потрібна лише множина унікальних елементів.

HashSet гарантує унікальність, але не зберігає порядок. Зате він миттєво робить математичні операції: об’єднання (union), перетин (intersect) чи різницю (except).

SortedSet теж зберігає лише унікальні елементи, але одразу сортує їх за зростанням. Вставка сюди обійдеться дорожче, зате ви завжди маєте відсортований набір.

Stack і Queue

Дві класичні структури для специфічних задач.

Stack працює за принципом LIFO (останній зайшов — перший вийшов). Ідеально для скасування дій (undo) або обходу в глибину (DFS).

Queue — це FIFO (перший зайшов — перший вийшов). Використовуйте для черги задач, обходу в ширину (BFS) або фонових робіт.

stack.Push(x); var y = stack.Pop();
queue.Enqueue(x); var z = queue.Dequeue();

Пам’ятка: як обрати колекцію

Задайте собі питання: як я буду з нею працювати?

  • Потрібен індекс і збереження порядку? Беріть List<T>.
  • Шукаєте значення за ключем? Ваш вибір — Dictionary<TKey,TValue>.
  • Важлива лише унікальність? Це HashSet<T>. А якщо ще й відсортовано — SortedSet<T>.
  • Останній зайшов — перший вийшов? Це Stack<T>. Перший зайшов — перший вийшов? Тоді Queue<T>.
