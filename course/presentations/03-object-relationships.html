Лекція 03

Відносини між об’єктами

Асоціація, агрегація і композиція — як об’єкти володіють одне одним.

менеджерробітникпроєкт

Три типи зв’язку

Асоціація

Знають один про одного. Час життя не зв’язаний. Менеджер керує робітниками — без менеджера робітники лишаються.

Агрегація

Ціле і частини, частина живе окремо. Проєкт закрили — робітник лишається в компанії.

Композиція

Частина не існує без цілого. Дім і кімната. У коді — private поле, створене всередині власника.

Код: компанія

public class Project {
  public List<Worker> Team { get; } = new(); // агрегація
}

public class Company {
  private readonly List<Manager> _managers = new(); // композиція
  public Manager HireManager(string name) {
    var m = new Manager(name);
    _managers.Add(m);
    return m;
  }
}

Як розрізнити їх на іспиті

  • Хто створює об’єкт? Якщо власник — підозра на композицію
  • Чи можна передати частину в інше ціле? Так → агрегація / асоціація
  • UML: композиція — зафарбований ромб, агрегація — порожній

Місток до DI

Якщо об’єкт не створює залежність сам, а отримує її ззовні — це вже асоціація і крок до впровадження залежностей.
