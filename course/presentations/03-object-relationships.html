Лекція 03

Відносини між об’єктами

Асоціація, агрегація та композиція: як об’єкти володіють одне одним і хто за кого відповідає.

менеджерробітникпроєкт

Три типи зв’язку

Наскільки об’єкти залежать один від одного?

Асоціація

Вони просто знають одне про одного, але їхній час життя не зв’язаний. Наприклад, менеджер керує робітниками. Звільнили менеджера — робітники лишаються працювати.

Агрегація

Тут уже є ціле і його частини, але частина може жити окремо. Проєкт закрили — робітник просто переходить на інший, він лишається в компанії.

Композиція

Найжорсткіший зв’язок: частина не існує без цілого. Зруйнували дім — зникла і кімната. У коді це зазвичай private поле, яке створюється прямо всередині власника.

Як це виглядає в коді

Хто кого створює.

public class Project {
  public List<Worker> Team { get; } = new(); // агрегація: ми просто додаємо існуючих робітників
}

public class Company {
  private readonly List<Manager> _managers = new(); // композиція: компанія сама створює менеджерів
  public Manager HireManager(string name) {
    var m = new Manager(name);
    _managers.Add(m);
    return m;
  }
}

Як розрізнити їх на іспиті

Кілька простих питань:

  • Хто створює об’єкт? Якщо власник робить це сам — у вас підозра на композицію.
  • Чи можна передати цю частину в інше ціле? Якщо так — це агрегація або асоціація.
  • Як це малювати на UML? Композиція — це зафарбований ромб, а агрегація — порожній.

Місток до DI

Зверніть увагу: якщо об’єкт не створює залежність сам, а отримує її ззовні — ми послаблюємо зв’язок до асоціації. Це ваш перший крок до впровадження залежностей (Dependency Injection).
